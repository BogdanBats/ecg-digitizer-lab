# ECG Photo Digitizer & Clinical Caliper Workstation

Приложение для конвертации бумажных и сфотографированных ЭКГ в калиброванный цифровой сигнал (500 Гц, мВ / мкВ), интерактивной расстановки кардиологических калиперов (`P_on`, `P_peak`, `P_off`, `QRS_on`, `R_peak`, `J / QRS_off`, `T_on`, `T_peak`, `T_off`, `R_+1`) и автоматического расчёта длительностей зубцов, интервалов, сегментов, электрической оси сердца (ЭОС) и вольтажных индексов.

## Реализованные методы оцифровки

1. **Hybrid Ensemble (`hybrid_ensemble`, по умолчанию)** — ансамбль предобученной нейросети **Open-ECG-Digitizer U-Net** (Ahus-AIM, 22.6M параметров, 4 класса: сетка, сигнал, текст, фон) + распознавание подписей отведений **LeadName U-Net** + авто-выделение области бланка и коррекция наклона преобразованием Хафа (**Felix Krones et al.**) + автокорреляционный расчёт шага миллиметровки (`PixelSizeFinder`) + трассировка перекрывающихся зубцов QRS методом динамического программирования **Viterbi / Hungarian matching** (**dangnh0611 Kaggle 5th Place**).
2. **Open-ECG-Digitizer (`open_ecg_unet`)** — оригинальный нейросетевой конвейер Ahus-AIM (`weights/unet_weights_07072025.pt` и `weights/lead_name_unet_weights_07072025.pt`).
3. **Kaggle 5th Place Heatmap + Viterbi DP (`dangnh_heatmap_dp`)** — тепловая карта высокой чёткости + алгоритм Витерби с подавлением соседних изолиний для точного разделения накладывающихся высокоамплитудных комплексов R/S.
4. **ECG-Digitiser Classical Hough + Color Decoupling (`krones_hough_cv`)** — цветовое разделение миллиметровой сетки и чернил в пространстве RGB/LAB + преобразование Хафа (1-е место PhysioNet Challenge 2024).

## Измеряемые клинические параметры и калиперы

- **Режимы калиперов:**
  - **Фидуциальные калиперы (P–QRS–T):** 10 перетаскиваемых мышью меток с пересчётом всех таблиц в реальном времени (60 FPS).
  - **Свободный циркуль ($\Delta t / \Delta V$):** измерение любого временного интервала (мс, мм, эквивалентная ЧСС), амплитуды (мВ, мкВ, мм) и скорости нарастания/спада (мВ/с).
  - **Шагающий циркуль (Marching Calipers):** проверка регулярности ритма R–R или P–P на кратных интервалах ($\pm 1\times, 2\times, 3\times\dots$).
- **Расчёты:**
  - ЧСС (уд/мин), интервал RR (мс), вариабельность (SDNN, RMSSD)
  - Длительность зубца P (мс, мм), интервал PQ / PR (мс, мм), сегмент PQ (мс, мм), индекс Макруза ($P / PQ_{\text{сегм}}$)
  - Длительность комплекса QRS (мс, мм), время внутреннего отклонения VAT (мс, мм), амплитуды зубцов P, Q, R, S, T (мВ, мм)
  - Уровень точки J, смещение сегмента ST на **J+60 мс** и **J+80 мс** (мВ и мм), длительность и наклон сегмента ST (мВ/с)
  - Интервал QT (мс), **4 формулы корригированного QTc** (Bazett, Fridericia, Framingham, Hodges), интервалы JT / JTc, интервал **Tp–Te** ($T_{\text{peak}}\text{–}T_{\text{end}}$) и отношение $Tp\text{-}Te / QT$, сегмент TP
  - **Электрическая ось сердца (ЭОС):** углы $\alpha$ для QRS, P, T, угол QRS–T (с круговой гексаксиальной диаграммой Бейли/Эйнтховена)
  - **Индексы гипертрофии:** индекс Соколова–Лайона ($S_{V1} + R_{V5/V6}$) и Корнельский вольтажный индекс ($R_{aVL} + S_{V3}$)
- **Экспорт:** CSV (все отведения в мВ и мкВ с временной шкалой 500 Гц), JSON-отчёт и печатный клинический протокол.

## Установка

```bash
pip install -r requirements.txt
```

Нейросетевые методы (`hybrid_ensemble`, `open_ecg_unet`, `dangnh_heatmap_dp`) требуют PyTorch и исходники
[Open-ECG-Digitizer](https://github.com/Ahus-AIM/Open-ECG-Digitizer) с весами (Git LFS) в `vendor/Open-ECG-Digitizer/`:

```bash
git lfs install
git clone https://github.com/Ahus-AIM/Open-ECG-Digitizer vendor/Open-ECG-Digitizer
```

Если PyTorch, исходники или файлы `weights/*.pt` отсутствуют, сервер всё равно запускается. Нейросетевые методы
помечаются в интерфейсе как недоступные, а запросы автоматически выполняются классическим `krones_hough_cv`
(с предупреждением в ответе `digitization.warnings`).

## Запуск

```bash
python run.py
```

После запуска откройте в браузере: `http://127.0.0.1:8055`

Ограничения API: файл до 40 МБ; изображения больше 4000 px по длинной стороне автоматически уменьшаются.
Оцифровка выполняется в пуле потоков и не блокирует остальные запросы.

## Калибровка сетки и автоопределение раскладки

- **Шаг сетки (пикс/мм)** ищется совместно по обеим осям (сетка ЭКГ квадратная) в диапазоне, ограниченном
  физически правдоподобной шириной видимой бумаги (70–420 мм), затем каждая ось уточняется в пределах ±8 %
  (перспектива). Это исправляет крупные планы термолент, где исходный `PixelSizeFinder` (рассчитанный на 18–95
  больших клеток в кадре) цеплялся за полупериод 2.5 мм или за точки 1 мм. Если поиск не уверен, используется
  исходный `PixelSizeFinder`, затем оценка по размеру листа (с предупреждением).
- **Раскладка (`auto`)** выбирается сравнением гипотез о числе рядов (1/3/4/5/6/7/12): каждая оценивается по тому,
  какую долю пиков горизонтальной проекции сигнала объясняют её ряды, со штрафом за пропущенные пики, «пустые»
  ряды и физически невозможный шаг рядов (< 0.85 × усиление, т.е. < 8.5 мм при 10 мм/мВ).
- Автообрезка листа не разрезает A4 12×1 по пустой полосе между группами отведений, но по-прежнему отделяет
  термоленту от стола.

На 8 примерах из `example/` (метод hybrid, раскладка `auto`) раскладка определяется верно во всех случаях,
а ЧСС совпадает с указанной в описаниях (90 / 59 / 58 / 73 уд/мин) с точностью ±3 уд/мин. Классический метод
`krones_hough_cv` в режиме `auto` ненадёжен (его карта сигнала реагирует на линии сетки) — для него выбирайте
раскладку вручную.

## Автоанализ и заключение (стенд калиперов)

Кнопка **«▶ Автоанализ»** в стенде калиперов (`POST /api/autoanalysis`, модули `app/core/ecg_autoanalysis.py`,
`app/core/ecg_interpretation.py`):

1. **QRS** — консенсус опубликованных детекторов NeuroKit2 (neurokit, Kalidas 2017, Elgendi 2010, Pan–Tompkins 1985,
   Engelse–Zeelenberg) и встроенного детектора: комплекс принимается, если его нашло большинство методов; затем
   слияние по одновременно записанным отведениям (большинство отведений группы) и единая опорная точка —
   пик пространственной скорости.
2. **Медианный комплекс** каждого отведения (без экстрасистол и артефактных зон), как в аппаратных анализаторах.
3. **Глобальная разметка** по всем отведениям группы: начало/конец QRS — по пространственной скорости относительно
   уровня сегментов PR и ST–T (короткие провалы на вершинах зубцов не считаются границей), конец T — касательная +
   порог по пространственной величине, P — согласованный по времени бугорок в ≥ 1/4 отведений.
   DWT-разметка NeuroKit2 (Martinez 2004) была проверена и отклонена: на этих сигналах она ставила начало QRS
   внутрь P и пропускала P/QRS.
4. **Интерпретация** — правила с явными критериями (каждая находка показывает обоснование): синусовый ритм / ФП /
   эктопический ритм / экстрасистолы; ЭОС (отечественная классификация или AHA); АВ-блокада I ст., предвозбуждение,
   БПНПГ/БЛНПГ/неполная БПНПГ/гемиблоки; ГЛЖ (Соколов–Лайон, Корнелл с поправкой на пол, произведение Корнелла,
   Пегеро–Ло Прести), ГПЖ, перегрузка предсердий; подъём/депрессия ST и патологические Q по 4-му универсальному
   определению ИМ (пороги V2–V3 по полу и возрасту, при БЛНПГ ST не оценивается, дискордантный подъём ST в V1–V3
   при ГЛЖ с ST/S < 25 % — вторичный); удлинение/укорочение QTc с учётом пола; низкий вольтаж.
   ST/T не оцениваются в отведениях, где уровень PR и TP медианного комплекса расходится > 2.5 мм.

Точность на синтетической 12-канальной ЭКГ с точно известными границами: ЧСС ±1, QRS ±6 мс (в т. ч. широкие
120–140 мс), PR −10 мс, QT −13…−20 мс (касательный метод), ЭОС ±6°.

Заключение формируется из отмеченных находок и **редактируется** вручную (правки не перезаписываются без
подтверждения, черновик сохраняется в браузере для каждого файла). **«↻ По текущим калиперам»** пересчитывает
заключение по исправленным меткам R и калиперам: интервалы, границы которых врач передвинул на активном отведении,
берутся с этого отведения, остальное — автоматически. Пол, возраст и классификация ЭОС меняют пороги и формулировки
сразу. **«Печать заключения»** — бланк с данными пациента, измерениями, записью ЭКГ, заключением и подписью врача;
заключение также входит в экспорт JSON. Автоанализ требует Python-сервера (в статической версии недоступен).

## Цифровые записи электрокардиографов и холтеров

Кнопка загрузки и перетаскивание принимают, кроме фото и PDF, «родные» файлы аппаратов (формат определяется по
содержимому, `app/core/ecg_formats.py`):

| Формат | Файлы | Примечание |
|---|---|---|
| EDF / EDF+ / BDF | `.edf`, `.bdf`, `.rec` | большинство холтеров и ПК-электрокардиографов; канал аннотаций пропускается |
| ISHNE 1.0 | `.ecg`, `.ishne` | стандарт холтеровских записей |
| WFDB / PhysioNet | `.hea` + `.dat` или `.zip` | форматы 16, 212, 80, 61 |
| GE MUSE XML | `.xml` | полоса ритма (`Rhythm`), base64 |
| HL7 aECG (FDA) | `.xml` | серия ритма; усреднённые комплексы (`derivation`) игнорируются |
| DICOM ECG | `.dcm` | 12-канальные и общие ECG Waveform IOD (pydicom) |
| CSV / TXT | `.csv`, `.txt` | столбцы отведений (мВ или мкВ), время — для частоты; читает и собственный экспорт CSV |

Имена отведений приводятся к стандарту (`MLII` → II, `Lead aVL` → aVL, `MDC_ECG_LEAD_V1` → V1); у 8-канальных
записей (GE, HL7) III, aVR, aVL, aVF вычисляются из I и II по Эйнтховену/Гольдбергеру. Сигнал переводится в мВ и
500 Гц. Пол, возраст и имя пациента из заголовка подставляются в заключение, если поля пустые. SCP-ECG и Philips XML
(сжатие XLI) пока не поддерживаются — сообщение предлагает экспорт в EDF / DICOM / HL7.

Для цифровой записи **раздел 1 (верификация оцифровки фото) скрыт** — стенд калиперов занимает всю ширину; галочка
«Обзор всех отведений» на панели записи возвращает только обзор каналов (без фото-вкладок). Длинные записи (холтер)
открываются фрагментами 10–120 с: поле «Начало», ◀ ▶ и **тренд ЧСС за всю запись** (медиана и 5–95 % по окнам,
жёлтая/красная полоса — нерегулярный ритм, ▼ — паузы > 2 с); клик по тренду открывает этот момент. Запись держится в
памяти сервера (`/api/signal_segment`), повторная загрузка файла при листании не нужна.

## Циркуль RR → аритмии (раздел 2)

Режим **«Циркуль RR → аритмии»**: две ножки (с привязкой к R, Alt — без привязки; ручка ⇔ двигает циркуль целиком)
задают размах, который проецируется на все RR канала — от каждого R («на каждый RR») или шагами от первой ножки
(«марш», как классический шагающий циркуль для зубцов P). Каждый RR помечается N (в допуске ±5–20 %),
S (короче — преждевременный), L (длиннее — пауза) или ? (артефакт); клик по интервалу переходит к комплексу.
По последовательности ищется наименьший повторяющийся период и называется по реальным RR его фаз (а не по положению
ножек): бигеминия / тригеминия / квадригеминия с оценкой компенсаторной паузы, паузы ≈ 2 циклов (блокада 3:2,
(n+1):n), укорочение RR перед паузой < 2 циклов (периодика Венкебаха), пробежки, нерегулярный ритм без паттерна.
Вывод добавляется в заключение кнопкой «В заключение». Названия паттернов — подсказка для дифференциального
диагноза (экстрасистолия против групповых комплексов при блокаде), окончательно решают зубцы P и форма QRS.

## Калипер ЭОС (раздел 5) и положение калиперов (раздел 6)

**Калипер ЭОС** — окно A–B на комплексе активного R (отведения I и aVF·2/√3): площадной средний вектор окна,
вектор по сумме зубцов и максимальный мгновенный вектор; при наведении — мгновенный вектор в точке. Пресеты:
QRS, начальные / терминальные 40 мс QRS, P, ST (J…J+80), T; вектор окна рисуется на гексаксиальной схеме (К).
В **сводной матрице** у каждого отведения — миниатюра комплекса с калиперами P / QRS / T (вручную сдвинутые —
фиолетовые) и их положение в мс от R; матрица обновляется при перетаскивании калиперов.

## Навигация, отмена правок и горячие клавиши

Закреплённая панель вверху: переход к разделам 1–7 (подсвечивается текущий) и живые показатели активного
отведения и комплекса (ЧСС, PQ, QRS, QT/QTcF, ЭОС; жёлтые/красные — вне нормы, клик ведёт к разделу).
**Ctrl+Z / Ctrl+Y** (и кнопки ↶ ↷) отменяют и возвращают правки меток R, калиперов и артефактов — до 40 шагов
для текущей записи. Клавиши: ← → — комплекс, ↑ ↓ — отведение, 1–6 — режим стенда, + − 0 — развёртка,
PgUp/PgDn — фрагмент холтера, A — автоанализ, G затем 1–7 — раздел, ? — справка. Статус показывает время долгих
операций, клик по нему открывает журнал сообщений.

## Инструменты анализа (раздел 7)

Вкладки по активному отведению, пересчитываются при правке меток R и артефактов:

- **Ритмограмма и ВСР** — RR во времени (клик по точке — к комплексу), гистограмма, диаграмма Пуанкаре с
  эллипсом SD1/SD2; SDNN, RMSSD, pNN50, SDSD, CV, SD1/SD2; при участке ≥ 1 мин — LF, HF, LF/HF (Ломб–Скаргл).
  NN — RR между комплексами основной формы без артефакта и без отклонения > 20 % от локальной медианы.
  Участок < 30 с не анализируется. Совпадение с NeuroKit2 на 5-минутном ряде: SDNN, RMSSD, SD1, SD1/SD2 —
  до сотых, LF/HF — со `scipy.signal.lombscargle`.
- **Наложение комплексов** — все комплексы, совмещённые по R, с медианным комплексом основной формы
  (наибольший кластер похожих QRS; при равных — с более длинным предшествующим RR, поэтому бигеминия
  разделяется верно). Каждый комплекс: основная форма, преждевременный с той же формой (наджелудочковый?),
  преждевременный с иной формой (желудочковый / аберрантный?), иная форма без преждевременности.
- **Дисперсия QT** — QRS и окончание T каждого отведения от начала QRS; QTd и QTcd. Не входят отведения с T
  < 0,1 мВ, плохим качеством, нестандартные и с QT, отличающимся от медианы > 20 % (вероятная ошибка T_off).
  При автоматических границах вывод помечается «проверьте T_off»; предупреждение, если калиперы синхронных
  отведений стоят на разных комплексах.
- **Спектр и шум** — спектр мощности (Welch), дрейф изолинии, наводка 50/60 Гц над соседними частотами,
  ВЧ-шум вне QRS, отношение сигнал/шум.

- **Сравнение с предыдущей** — «Сохранить текущую как эталон» запоминает медианные комплексы всех стандартных
  отведений и интервалы (в браузере или в файл .json для карты пациента). При открытии следующей ЭКГ комплексы
  «было/стало» накладываются по 12 отведениям; находки: новый подъём / депрессия ST ≥ 1 мм (J+60), смена знака T,
  изменение формы QRS (r < 0,9; почти изоэлектрические отведения не сравниваются), расширение QRS ≥ 20 мс,
  удлинение QTc ≥ 60 мс или выше 500, PQ, сдвиг ЭОС ≥ 30°. Синхронные отведения совмещаются по R одного опорного
  отведения (II, V5, I…), иначе отведение с глубоким S сдвигается между записями. Интервалы точнее, если на
  обеих ЭКГ выполнен автоанализ (иначе — медиана по отведениям). Проверено на паре синтетических ЭКГ (подъём ST
  V2–V4, инверсия T V5–V6, QRS 90 → 130 мс — найдено всё, ложных находок нет) и на отрицательном контроле.

Кнопка «В заключение» добавляет вывод открытой вкладки в текст заключения. Под заключением — **шаблоны фраз**
(ритм, экстрасистолия, ЭОС, проводимость, гипертрофия, ST–T, динамика и рекомендации) с поиском и своими фразами;
клик вставляет фразу в позицию курсора, многоточие «…» сразу выделяется для ввода.

**Фильтры цифровых записей** (панель записи): изолиния 0,67 Гц, мониторный 0,67–40 Гц, диагностический
0,05–150 Гц и режектор 50/60 Гц — с нулевой фазой (`sosfiltfilt`), фильтруется фрагмент с запасом 5 с по краям.
Тест: дрейф 0,5 мВ и наводка 50 Гц убираются, смещение ST сохраняется с точностью 0,04 мВ, амплитуда R — 5 %.
Мониторный 40 Гц снижает амплитуду острых QRS — для измерений используйте «изолинию» или «диагностический».

## Трассировка рядов

- Ряды каждой колонки привязаны к сетке рядов всего листа и уточняются локально (±0.45 шага — допускает
  смещение колонок из-за перспективы), поэтому колонка с бледными верхними рядами больше не «съезжает» вниз.
- Если видимых рядов меньше, чем в раскладке, недостающие добавляются в настоящие разрывы (≥ 1.8 шага) или
  с краёв листа, а не накладываются на соседние ряды (раньше два отведения могли получить одну и ту же линию).
- Трекер Viterbi работает в два прохода: во втором каждая строка трассируется с учётом линий ВСЕХ соседних
  рядов (идти вдоль чужой изолинии так же «дорого», как по пустой бумаге; пересекать её зубцом можно), а яркость
  нормируется по своему ряду, чтобы бледный ряд не проигрывал яркому соседу.
- Мелкие сканы (< 3.3 пикс/мм) перед обработкой увеличиваются до ~5 пикс/мм: иначе QRS шириной 1–2 px почти
  не виден нейросети и ряды выходят плоскими.

На 8 примерах (hybrid, раскладки из пресетов) число отведений с плохим качеством трассировки снизилось с 23 до 2.
Известное ограничение: на фото 00-34-51 (лист в руке) тесно стоящие верхние ряды I–III сливаются, и грудные
отведения подписываются со сдвигом на два ряда — это исправит только распознавание подписей отведений.

## Контроль качества оцифровки

- **Калибровочный импульс 1 мВ** ищется в полях листа на карте тёмных чернил (нейросеть сегментации импульсы
  не выделяет): П-образная фигура, открытая снизу и пустая внутри — так отсекаются клетки сетки, буквы и кнопки.
  Высота импульса сверяется с заданным усилением; при расхождении интерфейс предлагает пересчитать с усилением,
  которое показывает импульс (например, «Применить 10 мм/мВ»). Импульс, попавший внутрь полосы отведения,
  вырезается из сигнала, чтобы не считаться комплексом QRS. Ширина импульса у разных аппаратов разная
  (на примерах 1.8–3.7 мм при 25 мм/с), поэтому скорость по ней не проверяется.
- **Качество каждого отведения** (`digitization.lead_quality`: `ok` / `warn` / `bad` + причины): уход линии с
  сигнала (скачок в соседний ряд или ровная «полка» по пустой бумаге дольше 0.12 с), совпадение с соседним
  отведением, обрезанные вершины, плоская линия, амплитуда > 5 мВ. Отметки — на кнопках отведений и в таблице;
  линии, исправленные вручную, помечаются отдельно.

`numba` (необязательно) ускоряет трассировку Viterbi примерно в 10 раз; без неё используется эквивалентный
NumPy-код с теми же результатами.

## Тесты

```bash
python -m pytest tests -q
```

Тесты проверяют клиническую математику на синтетических ЭКГ с известным ответом (ЭОС по диполю, QTc, ЧСС,
индекс Соколова–Лайона) и API-эндпоинты (валидация, path traversal, уменьшение больших фото, сквозная оцифровка).
`tests/test_formats.py` записывает синтетическую 12-канальную ЭКГ в каждый цифровой формат
(`tests/ecg_format_writers.py`) и сверяет прочитанные амплитуды, а также тренд ЧСС и паузы синтетического холтера.

## Статическая версия (Firebase Hosting)

`public/` — копия фронтенда без Python-сервера. Если `/api/config` недоступен, браузер переключается на
упрощённую оцифровку на Canvas: раскладку нужно выбрать вручную, а границы P/QRS/T ставятся по шаблону от R
и требуют проверки калиперами. Амплитуды, ЭОС и индексы ГЛЖ при этом измеряются по реальному сигналу.

После правок в `app/static/` синхронизируйте копию (при `firebase deploy` это проверяется автоматически):

```bash
python tools/sync_public.py
```
