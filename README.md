# ECG Photo Digitizer & Clinical Caliper Workstation

Приложение для конвертации бумажных и сфотографированных ЭКГ в калиброванный цифровой сигнал (500 Гц, мВ / мкВ), интерактивной расстановки кардиологических калиперов (`P_on`, `P_peak`, `P_off`, `QRS_on`, `R_peak`, `J / QRS_off`, `T_on`, `T_peak`, `T_off`, `R_+1`) и автоматического расчёта длительностей зубцов, интервалов, сегментов, электрической оси сердца (ЭОС) и вольтажных индексов.

## Реализованные методы оцифровки

1. **Hybrid Ensemble (`hybrid_ensemble`, по умолчанию)** — ансамбль предобученной нейросети **Open-ECG-Digitizer U-Net** (Ahus-AIM, 22.6M параметров, 4 класса: сетка, сигнал, текст, фон) + распознавание подписей отведений **LeadName U-Net** + авто-выделение области бланка и коррекция наклона преобразованием Хафа (**Felix Krones et al.**) + автокорреляционный расчёт шага миллиметровки (`PixelSizeFinder`) + трассировка перекрывающихся зубцов QRS методом динамического программирования **Viterbi / Hungarian matching** (**dangnh0611 Kaggle 5th Place**).
2. **Open-ECG-Digitizer (`open_ecg_unet`)** — оригинальный нейросетевой конвейер Ahus-AIM (`weights/unet_weights_07072025.pt` и `weights/lead_name_unet_weights_07072025.pt`).
3. **Kaggle 5th Place Heatmap + Viterbi DP (`dangnh_heatmap_dp`)** — тепловая карта высокой чёткости + алгоритм Витерби с подавлением соседних изолиний для точного разделения накладывающихся высокоамплитудных комплексов R/S.
4. **ECG-Digitiser Classical Hough + Color Decoupling (`krones_hough_cv`)** — цветовое разделение миллиметровой сетки и чернил в пространстве RGB/LAB + преобразование Хафа (1-е место PhysioNet Challenge 2024).

## Измеряемые клинические параметры и калиперы

- **Режимы калиперов:**
  - **Фидуциальные калиперы (P–QRS–T):** 10 перетаскиваемых мышью меток с пересчётом всех таблиц в реальном времени (60 FPS).
  - **Свободный циркуль ($\Delta t / \Delta V$):** измерение любого временного интервала (мс, мм, эквивалентная ЧСС), амплитуды (мВ, мкВ, мм) и скорости нарастания/спада (мВ/с).
  - **Шагающий циркуль (Marching Calipers):** проверка регулярности ритма R–R или P–P на кратных интервалах ($\pm 1\times, 2\times, 3\times\dots$).
- **Расчёты:**
  - ЧСС (уд/мин), интервал RR (мс), вариабельность (SDNN, RMSSD)
  - Длительность зубца P (мс, мм), интервал PQ / PR (мс, мм), сегмент PQ (мс, мм), индекс Макруза ($P / PQ_{\text{сегм}}$)
  - Длительность комплекса QRS (мс, мм), время внутреннего отклонения VAT (мс, мм), амплитуды зубцов P, Q, R, S, T (мВ, мм)
  - Уровень точки J, смещение сегмента ST на **J+60 мс** и **J+80 мс** (мВ и мм), длительность и наклон сегмента ST (мВ/с)
  - Интервал QT (мс), **4 формулы корригированного QTc** (Bazett, Fridericia, Framingham, Hodges), интервалы JT / JTc, интервал **Tp–Te** ($T_{\text{peak}}\text{–}T_{\text{end}}$) и отношение $Tp\text{-}Te / QT$, сегмент TP
  - **Электрическая ось сердца (ЭОС):** углы $\alpha$ для QRS, P, T, угол QRS–T (с круговой гексаксиальной диаграммой Бейли/Эйнтховена)
  - **Индексы гипертрофии:** индекс Соколова–Лайона ($S_{V1} + R_{V5/V6}$) и Корнельский вольтажный индекс ($R_{aVL} + S_{V3}$)
- **Экспорт:** CSV (все отведения в мВ и мкВ с временной шкалой 500 Гц), JSON-отчёт и печатный клинический протокол.

## Установка

```bash
pip install -r requirements.txt
```

Нейросетевые методы (`hybrid_ensemble`, `open_ecg_unet`, `dangnh_heatmap_dp`) требуют PyTorch и исходники
[Open-ECG-Digitizer](https://github.com/Ahus-AIM/Open-ECG-Digitizer) с весами (Git LFS) в `vendor/Open-ECG-Digitizer/`:

```bash
git lfs install
git clone https://github.com/Ahus-AIM/Open-ECG-Digitizer vendor/Open-ECG-Digitizer
```

Если PyTorch, исходники или файлы `weights/*.pt` отсутствуют, сервер всё равно запускается. Нейросетевые методы
помечаются в интерфейсе как недоступные, а запросы автоматически выполняются классическим `krones_hough_cv`
(с предупреждением в ответе `digitization.warnings`).

## Запуск

```bash
python run.py
```

После запуска откройте в браузере: `http://127.0.0.1:8055`

Ограничения API: файл до 40 МБ; изображения больше 4000 px по длинной стороне автоматически уменьшаются.
Оцифровка выполняется в пуле потоков и не блокирует остальные запросы.

## Калибровка сетки и автоопределение раскладки

- **Шаг сетки (пикс/мм)** ищется совместно по обеим осям (сетка ЭКГ квадратная) в диапазоне, ограниченном
  физически правдоподобной шириной видимой бумаги (70–420 мм), затем каждая ось уточняется в пределах ±8 %
  (перспектива). Это исправляет крупные планы термолент, где исходный `PixelSizeFinder` (рассчитанный на 18–95
  больших клеток в кадре) цеплялся за полупериод 2.5 мм или за точки 1 мм. Если поиск не уверен, используется
  исходный `PixelSizeFinder`, затем оценка по размеру листа (с предупреждением).
- **Раскладка (`auto`)** выбирается сравнением гипотез о числе рядов (1/3/4/5/6/7/12): каждая оценивается по тому,
  какую долю пиков горизонтальной проекции сигнала объясняют её ряды, со штрафом за пропущенные пики, «пустые»
  ряды и физически невозможный шаг рядов (< 0.85 × усиление, т.е. < 8.5 мм при 10 мм/мВ).
- Автообрезка листа не разрезает A4 12×1 по пустой полосе между группами отведений, но по-прежнему отделяет
  термоленту от стола.

На 8 примерах из `example/` (метод hybrid, раскладка `auto`) раскладка определяется верно во всех случаях,
а ЧСС совпадает с указанной в описаниях (90 / 59 / 58 / 73 уд/мин) с точностью ±3 уд/мин. Классический метод
`krones_hough_cv` в режиме `auto` ненадёжен (его карта сигнала реагирует на линии сетки) — для него выбирайте
раскладку вручную.

## Контроль качества оцифровки

- **Калибровочный импульс 1 мВ** ищется в полях листа на карте тёмных чернил (нейросеть сегментации импульсы
  не выделяет): П-образная фигура, открытая снизу и пустая внутри — так отсекаются клетки сетки, буквы и кнопки.
  Высота импульса сверяется с заданным усилением; при расхождении интерфейс предлагает пересчитать с усилением,
  которое показывает импульс (например, «Применить 10 мм/мВ»). Импульс, попавший внутрь полосы отведения,
  вырезается из сигнала, чтобы не считаться комплексом QRS. Ширина импульса у разных аппаратов разная
  (на примерах 1.8–3.7 мм при 25 мм/с), поэтому скорость по ней не проверяется.
- **Качество каждого отведения** (`digitization.lead_quality`: `ok` / `warn` / `bad` + причины): уход линии с
  сигнала (скачок в соседний ряд или ровная «полка» по пустой бумаге дольше 0.12 с), совпадение с соседним
  отведением, обрезанные вершины, плоская линия, амплитуда > 5 мВ. Отметки — на кнопках отведений и в таблице;
  линии, исправленные вручную, помечаются отдельно.

`numba` (необязательно) ускоряет трассировку Viterbi примерно в 10 раз; без неё используется эквивалентный
NumPy-код с теми же результатами.

## Тесты

```bash
python -m pytest tests -q
```

Тесты проверяют клиническую математику на синтетических ЭКГ с известным ответом (ЭОС по диполю, QTc, ЧСС,
индекс Соколова–Лайона) и API-эндпоинты (валидация, path traversal, уменьшение больших фото, сквозная оцифровка).

## Статическая версия (Firebase Hosting)

`public/` — копия фронтенда без Python-сервера. Если `/api/config` недоступен, браузер переключается на
упрощённую оцифровку на Canvas: раскладку нужно выбрать вручную, а границы P/QRS/T ставятся по шаблону от R
и требуют проверки калиперами. Амплитуды, ЭОС и индексы ГЛЖ при этом измеряются по реальному сигналу.

После правок в `app/static/` синхронизируйте копию (при `firebase deploy` это проверяется автоматически):

```bash
python tools/sync_public.py
```
